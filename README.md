
# Writing Assistant Extension Starter

This project is a browser writing assistant extension for Edge, built with WXT + React. It is designed as a privacy-first, local-first writing assistant with a secure rewrite gateway and explicit user approval before replacements are applied.

## Included
- content script that watches editable fields and triggers inline suggestions
- background worker and secure message flow
- popup controls for rewrite mode, tone, preview, and local/cloud behavior
- local grammar heuristics and rewrite pipeline
- remote gateway support for user-managed API subscriptions
- privacy safeguards such as masking and response sanitization

## Rewrite modes

The extension supports three modes:

1. Local AI
   - Runs on the user device
   - No external bill required
   - Best for spelling, grammar hints, lightweight local rewriting

2. Remote AI (user API key)
   - Uses the user’s own OpenAI / Azure / Anthropic / OpenRouter subscription
   - The user pays the AI provider directly
   - Best for stronger paraphrasing and tone-aware rewrite quality

3. Off
   - Disables AI rewrite but keeps local suggestions available when enabled


## Provider configuration

The extension can be configured for a provider strategy via environment-driven settings in WXT:

```bash
VITE_PROVIDER=local
VITE_GATEWAY_URL=http://localhost:3001/rewrite
VITE_EXTENSION_API_KEY=demo-local-key
VITE_MODEL=gpt-4o-mini
VITE_REWRITE_ENABLED=true
```

For production deployments, allow the user to provide their own API key or keep the AI mode local-only, rather than requiring the seller to purchase AI access for each user.

## Cached local AI engine (Ollama)

The gateway can cache the AI engine locally with [Ollama](https://ollama.com) so the engine is ready for users instantly and stays on-device.

The default engine is `qwen2.5:0.5b` — a tiny local chat model (~400 MB RAM) that **actually generates paraphrases on-device**. It powers the flow:

1. **Model warm-up** — on startup the gateway pulls the model if it is missing and keeps it loaded in memory (`keep_alive: 24h`, re-warmed every 30 minutes), so the engine is ready before the first user request.
2. **On-device generation** — Local AI rewrites are generated by the model; cloud providers are only used when you configure them in Remote AI mode.
3. **Response cache** — repeated or near-identical reworded requests are answered instantly from `api-gateway/.cache/semantic-cache.json` using fuzzy word-overlap matching (no embedding model, zero extra memory), even across gateway restarts.

Low-memory alternatives: `qwen2.5:1.5b` (~1.1 GB) or `gemma2:2b` (~1.6 GB) — run `npm run ai:warm qwen2.5:1.5b` or set `OLLAMA_GENERATE_MODEL`.

> The previous default, `paraphrase-multilingual:278m` (embedding-only, 563 MB), is **no longer pulled by default** because it cannot generate text. You can still opt in with `OLLAMA_EMBED_MODEL=paraphrase-multilingual:278m` to add embedding-based semantic caching (cosine >= 0.93) and fidelity ranking of rewrite variants.

### Setup

```bash
# 1. Install and start Ollama from https://ollama.com
# 2. Cache + warm the engine (one-time download of ~1.6 GB for gemma2:2b)
npm run ai:warm                # alternatives: npm run ai:warm qwen2.5:0.5b
                               #               npm run ai:warm qwen2.5:1.5b
# 3. Start the gateway — it re-warms the engine automatically
node api-gateway/server.js
```

### First-use automatic download

The app downloads the engine model itself the first time it is used — no CLI required.
The preset is **Ollama + gemma2:2b (~1.6 GB)**, and one click runs everything internally:

### Preset one-click setup (Ollama + Gemma)

Press **Download Ollama + Gemma** in the extension popup. The gateway then runs the
whole preset internally while the popup shows **“Ollama with Gemma is downloading”**
with live percent progress:

1. **Install Ollama** (only if its service is missing; Windows: silent winget install, then an official-installer fallback).
2. **Wait for the Ollama service** to answer on `http://127.0.0.1:11434`.
3. **Download `gemma2:2b`** with streaming per-layer progress (resumable).
4. **Warm it into memory** (`keep_alive: 24h`) so the first rewrite is instant.

Poll `GET /engine/setup` (same extension auth headers) for
`{ running, phase, message, percent, model, error }`; `POST /engine/setup` starts it
and `POST /engine/setup/cancel` stops it. All three require the extension key, so the
installer never runs from an unauthenticated web page.

If Ollama is already running (or the gateway cannot be reached), the popup falls back
to pulling the model straight into Ollama with the same progress bar.

`GET /health` reports engine readiness:

```json
{
  "ok": true,
  "engine": { "provider": "ollama", "generateModel": "gemma2:2b", "embedModel": null, "modelCached": true, "warm": true },
  "semanticCache": { "enabled": true, "size": 12, "hits": 40, "fuzzyHits": 8, "misses": 3 }
}
```

`POST /rewrite` responses include `cache` (`miss`, `exact`, `fuzzy` or `semantic`) and, on cache hits, `similarity`.

### Environment variables

| Variable | Default | Purpose |
| --- | --- | --- |
| `OLLAMA_HOST` | `http://127.0.0.1:11434` | Ollama server URL |
| `OLLAMA_GENERATE_MODEL` | `gemma2:2b` | On-device engine preset (`qwen2.5:0.5b`, `qwen2.5:1.5b`, …; set `false` to disable) |
| `OLLAMA_EMBED_MODEL` | *(unset)* | Optional embedding model (e.g. `paraphrase-multilingual:278m`) for embedding cache + fidelity ranking |
| `OLLAMA_KEEP_ALIVE` | `24h` | How long models stay resident in memory |
| `OLLAMA_PULL_IF_MISSING` | `true` | Auto-pull models on gateway startup |
| `OLLAMA_REWARM_INTERVAL_MS` | `1800000` | Interval to re-warm the engine and persist the cache |
| `OLLAMA_RANK_VARIANTS` | `true` | Rank rewrite variants by semantic fidelity (embedding model required) |
| `OLLAMA_WARM_TIMEOUT_MS` | `60000` | Timeout for loading the engine model into memory |
| `OLLAMA_ENGINE_RETRY_MS` | `60000` | Cooldown between background engine pull attempts on rewrite requests |
| `SEMANTIC_CACHE_ENABLED` | `true` | Enable the response cache |
| `SEMANTIC_CACHE_THRESHOLD` | `0.93` | Minimum cosine similarity for an embedding cache hit |
| `SEMANTIC_CACHE_FUZZY_THRESHOLD` | `0.85` | Word-overlap threshold for fuzzy cache hits (`0` disables) |
| `SEMANTIC_CACHE_MAX_ENTRIES` | `250` | Cache size cap (LRU eviction) |
| `SEMANTIC_CACHE_PERSIST` | `true` | Persist the cache to disk across restarts |
| `VITE_OLLAMA_HOST` | `http://127.0.0.1:11434` | Extension popup: Ollama host for readiness checks |
| `VITE_OLLAMA_GENERATE_MODEL` | `qwen2.5:0.5b` | Extension popup: engine model shown and warmed |
| `VITE_OLLAMA_AUTO_DOWNLOAD` | `true` | Extension: auto-download the engine model on first use |
| `VITE_LOCAL_VIA_GATEWAY` | `true` | Extension: route Local AI through the gateway when available |

The popup's **Local AI** panel shows engine readiness (`Ollama engine ready` / `Ollama engine not detected`) with **Check engine** and **Warm up engine** buttons. Everything degrades gracefully: without Ollama installed, the extension and gateway behave exactly as before.

## Edge deployment and packaging

Use the packaged build for side-loading or distribution review in Microsoft Edge:

```bash
npm run zip
```

This creates a distributable extension archive for review. For manual testing in Edge:
1. Open `edge://extensions`.
2. Enable Developer mode.
3. Choose `Load unpacked` and point at the generated `.output` folder, or install the generated zip package if your workflow requires it.

## Notes
- Remote rewrite requests are intentionally lightweight and privacy-aware.
- The gateway is a practical backend stub for the production API layer described in the roadmap.
- Rewrite actions require explicit user confirmation before applying text changes.

## Multi-shell strategy

- Browser extension shell for Edge/Chrome
- PWA shell for installable web app
- Outlook add-in shell for Microsoft 365 compose scenarios

The core rewrite logic is intentionally shared so the AI model selection and safety rules stay consistent across all surfaces.
